# Adversarial review, 2026-07-31 — verified findings

Twelve refute lenses over `main`, then 24 of the most serious findings independently
re-checked by a separate agent each, against the i.MX RT1060 RM rev.4 and the datasheets.

**18 CONFIRMED, 6 PARTIAL, 0 fully refuted at the mechanism level.** One verifier claim
was itself wrong — see *Corrections* at the end. That is the honest state of this
firmware, and it is why nothing here should go on a power stage yet.

Anything marked FIXED was fixed in this session and is **still not bench-verified**.

---

## Hardware damage

### 1. Every masked protective state drives inverted cells' gates ON — PARTLY FIXED
Schemes 2, 5 and 4-POD/APOD invert a cell's polarity (`OCTRL[POLA]/[POLB]=1`). Both
mechanisms that force outputs off act *before* polarity:
- `MASK` — RM 55.8.45.4, p.3191: "forcing the output to logic 0 prior to consideration
  of the output polarity"
- fault state `PWMAFS`/`PWMBFS` — RM 55.8.18.3, p.3158: "forced to logic 0 state prior
  to consideration of output polarity control"

So "off" renders as a **HIGH pin** — the gate is commanded on by the shutdown mechanism.
`OUTEN` stays set, so the pin is actively driven, not floating.

**FIXED (fault path):** the fault state is set per cell — `PWMAFS`/`PWMBFS` = state 1 on
inverted cells — covering the FlexPWM fault path and the ACMP hardware over-current trip.

**FIXED (mask path), 2026-07-31:** `MASK` has no per-cell state, so it cannot be made
polarity-aware directly. Instead `maskAllOutputsSafely()` clears `OCTRL[POLA]/[POLB]` on
the inverted cells *first*, then masks. All four call sites now use it —
`faultTripIsr`, `enterOtaSafeState`, `acmpFaultIsr`, and the refused-clear re-mask in
`applyPwmConfig` (that fourth site was missed by the original report and found during
verification). `clearFaultTrip()` calls `restoreCellPolarity()` before unmasking, so a
cleared fault does not resume with the 180° opposition silently absent.

`OCTRL` is not LDOK-buffered, so the writes take effect immediately rather than at a
reload.

**Residual, and it needs a scope:** between un-inverting and the mask landing there is a
window of a few CPU cycles in which the live waveform reaches the pins at the wrong
level — one short wrong-level edge. That is a bounded glitch against a permanently held
gate-on, so the trade is right, but *confirm the edge is as short as expected*. Masking
first and un-inverting afterwards would be worse: it would put both pins of a leg high
for that same window, which is the shoot-through case.

The durable fix remains not using polarity for carrier inversion at all.

**Refuted sub-claim:** there is no boot mask. At reset `MASK=0` and `OUTEN=0`.

The durable fix is to stop using polarity for carrier inversion entirely and use
`VAL2`/`VAL3` edge displacement. **Until then use scheme 1, 3 or level-shifted PD only.**

### 2. Incomplete `/settings.cfg` arms 50% duty on both channels
The boot load path does not apply `configDocComplete()`, so a settings file missing a
submodule subtree falls back to compiled defaults — `ChannelB.DutyCycle = 32768` — and
commands **both channels of that submodule at 50% concurrently**. Only the *import* path
checks completeness.

### 3. No-SD boot programs Sm42 from a divide-by-zero, then enables outputs
A fresh boot with no card takes the asymmetric-induction branch with `PwmFrequency = 0`,
computes `VALx` through a division by zero, and enables the outputs anyway.

### 4. Leaving complementary mode publishes stale `VAL4`/`VAL5`
`CTRL2[INDEP]` is unbuffered and is written before `LDOK` loads the new values, so
`PWM_B` runs the previous active duty for up to a full carrier period during the
transition.

### 5. Thermal derate is bypassed when MPPT drives the index
Derating is applied only inside `setModulationIndexTargetQ15`. With MPPT enabled and the
meter invalid, the tracker writes the index by another path and **the only
over-temperature protection is silently skipped.**

### 6. `Thermal.OneWirePin` / `FaultProtection.Pin` are unvalidated — PARTIAL
Network-settable and persisted. Pointing one at a live gate-drive pad re-muxes it to a
pulled-up GPIO input. Verifier rated the exploitability lower than reported but confirmed
the missing validation.

## Security / blocker

### 7. Unauthenticated one-request watchdog reset — FIXED 2026-08-01, not bench-verified
Every HTTP response write was an unbounded spin with nothing servicing WDOG1. A client
that stops reading (zero TCP window) stalled the firmware past 8 s and **reset a
generating inverter**. No authentication required, any GET.

**FIXED:** `m_writeBounded()` replaces `EthernetClient::writeFully()` at all three aWOT
write sites. It services the control tasks on every spin, yields, and abandons the
response once the peer has accepted nothing for the budget or the connection drops. Two
corrections were needed along the way, both worth recording because each reintroduced a
different half of the original problem:

1. The first version converted only `m_flushBuf()`. Both `Response::write()` overloads
   still called `writeFully()` directly, and between them they carry most of any
   response larger than one output buffer — so the reset stayed reachable.
2. The budget initially measured *total* time in a call rather than time *without
   progress*. Since `Client::write()` may accept only part of what it is offered, a peer
   reading steadily but slowly accumulated elapsed time without ever stalling and had its
   response truncated — the exact bug the original `writeFully()` dependency existed to
   fix. A host test caught it: 3000 bytes at 7 bytes per write lost more than half the
   body. The deadline now resets on every byte accepted.

### 8. MTP read-only patch omits opcode `0x9804` `SetObjectPropValue`
The only surviving route to `MTPStorage::rename` — and it is advertised to the host as
supported. The "read-only by design" claim in `PATCHES.md` is therefore false.

### 9. `configDocComplete()` checks presence, not shape
A scalar or empty section satisfies it, so an imported file can silently disarm fault
protection, the hardware current limit and thermal derating.

### 10. Negative `Content-Length` wedges `POST /api/ota` forever — PARTIAL
Real, but in the 401 drain loop rather than `otaIngestStream`. Pre-authentication, and
the watchdog is deliberately fed, so nothing recovers.

### 11. Duplicate `X-Auth-Pin` writes one byte past `authPinHeader` — CONFIRMED, minor
Pre-auth out-of-bounds write of a single `0x00`. Lands in padding on this build, so it is
currently harmless — but it is an unauthenticated OOB write.

## Major

- **`otaFlashCommit` erases after the last retry too** — retry exhaustion resets into a
  blank base image. Unrecoverable brick.
- **`otaVerifyImage` boot-data bound check wraps** — `bootDataPtr + 12` overflows
  `uint32_t`, giving an out-of-bounds read from a crafted image.
- **Idle TCP connections are never reaped** — eight of them exhaust the shared lwIP PCB
  pool and permanently disable the web server, MQTT and InfluxDB.
- **`writeInfluxDb` stalls `loop()` up to ~6.2 s** — `setConnectionTimeout(500)` does not
  bound QNEthernet's 5 s DNS resolve.
- **`runFeedbackLoop` fallback divides a 12-bit ADC result by 1023** — closed-loop
  regulation servos to a quarter of the setpoint whenever the capture ring is frozen.
- **DPWM3 indexes `v[3]`, one past the end**, whenever all three reference magnitudes tie
  (modulation index 0).
- **CMP can leave Continuous mode while driving FAULT0** — RM 65.4.1 says it *must* be
  continuous for that use.
- **`acmpConfigure()` disarms FAULT0 and clears `FFLAG0` before re-arming** — every
  current-limit settings change leaves a live, unprotected window.
- **`saveConfiguration()` was not atomic** — FIXED this session: temp file, flush, swap.

## Corrections

**A verifier was wrong.** One claimed `FILE_WRITE` lacks `O_CREAT`, so
`saveConfiguration()` could never recreate the file it had just deleted. In this SdFat
`FILE_WRITE` is `(O_RDWR | O_CREAT | O_AT_END)`. The *non-atomicity* was real and is
fixed; the "cannot recreate" claim was not. Verification catches most things, not
everything.

**The host test suite cannot see any of this.** 278 tests pass and the firmware builds at
every point above — including while it was publishing its own credential and while three
successive versions of the pair-denial logic were driving both switches of a leg on
together. The suite exercises pure headers; every serious defect found in this project
has lived in registers, ISRs, boot order or the network path.
