# Adversarial release review — 2026-08-01

## Decision

**Decision at the reviewed commit: NO-SHIP for an energised or unattended power
stage.** The reviewed build could start outputs before protection was armed, miss an
already-active fault, accept unrepresentable switching parameters, and lose
supervisory control during blocking operations.

> **Post-review status:** every reproducible software finding below has been
> remediated on the `release-hardening` branch and carries native regression coverage
> where the logic is host-testable. The decision nevertheless remains **NO-SHIP for a
> real power stage** until [BENCH_CHECKS.md](BENCH_CHECKS.md) proves the register,
> pin, analogue, interrupt-latency, power-loss and recovery behavior on hardware.
> Plaintext management, product-grade signed/A-B update, tamper-proof logs and the
> QNEthernet licence decision are architectural gates, not bugs this patch can erase.

Do not interpret a successful build, passing native tests, or a low measured ISR time
as evidence that the whole system is safe. The current host suite exercises portable
logic; it cannot observe pin muxing, FlexPWM register ordering, interrupt masking,
network stalls, flash-copy failure, SD power loss, or real gate-driver behaviour.

## Release blockers — fix before any powered bench test

### 1. Hold every output inhibited until all protection is armed

`setup()` calls `configurePwm()` before GPIO fault protection, the ACMP/XBAR/FlexPWM
fault path, and WDOG1. `setupSubmodule()` starts counters, enables timer outputs and
asserts LDOK during that first call. A saved non-zero configuration can therefore
switch the pins during a real unprotected boot window.

The GPIO fault path is edge-triggered and never checks the current input level. An
active-high fault already high at boot (or active-low fault already low) produces no
edge and is missed. The same issue applies when the fault pin is reconfigured.

A direct `TEMPSENSE_RST_B` reset does not guarantee a valid Teensy CrashReport. While
hot, the core may repeatedly reset; after cooling, `setup()` loads the saved active
configuration and starts PWM because there is no persistent temperature-reset inhibit.
The retained `SRC_SRSR` bit is diagnostic state, not a restart interlock.

**Required gate:** start with a hardware/global output inhibit asserted; configure and
validate every protection source; sample each source as a level; refuse startup while
any source is active; arm the watchdog before lengthy bring-up; then deliberately
release the inhibit. A watchdog or lockup reset must not automatically resume a saved
active output without an explicit restart policy.

Evidence: `src/main.cpp:247-296`, `src/pwm_utils.cpp:216-339`,
`src/pwm_utils.cpp:1160-1185`; i.MX RT1060 RM Rev. 4, FlexPWM `RUN`, `OUTEN`,
`MASK` and fault-control registers; Teensy 4.1 core `interrupt.c` edge setup.

### 2. Make the carrier and hardware timing one validated source of truth

`Pwm.Tm2.SpwmCarrierFrequency` drives DDS, soft-start, PLL, dead-time compensation,
dither, capture metadata and missed-cycle calculations. The actual SM20 interrupt and
switching rate comes from `Pwm.Tm2.Sm20.PwmFrequency`; SM21-SM23 each have another
independent value. There is no equality check or propagation.

The compiled defaults are 20 kHz for the mathematical carrier and 1 kHz for every
FlexPWM2 submodule. If 50 Hz SPWM is enabled without correcting all fields, the DDS is
advanced at 1/20 of the assumed cadence and produces about 2.5 Hz. Cells may also run
at different physical carriers.

**Required gate:** use one canonical carrier setting, derive every active cell period
and all DSP/control coefficients from the period the hardware actually accepted, and
apply all cells as one checked transaction. Reject imported mismatches.

Evidence: `src/config_json.h:28-46`, `src/pwm_utils.cpp:530-565`,
`src/pwm_utils.cpp:721-759`, `src/pwm_utils.cpp:914-923`.

### 3. Reject frequencies and edge positions the FlexPWM hardware cannot represent

The parent validator accepts per-submodule frequencies down to 1 Hz. At a 150 MHz
FlexPWM clock, the `/128` prescaler and 16-bit period permit a minimum of about
17.882 Hz. The pinned eFlexPwm wrapper casts `pwmClock / freq` directly to `uint16_t`,
returns success, and caches the requested value:

| Requested | Stored period | Approximate output |
|---:|---:|---:|
| 1 Hz | 57,763 | 20.29 Hz |
| 5 Hz | 37,767 | 31.03 Hz |
| 17 Hz | 3,397 | 344.97 Hz |
| 18 Hz | 65,104 | 18.00 Hz |

This fix belongs in the **eFlexPwm repository first**, followed by a parent gitlink
update. The parent should still validate against the actual timer clock and chosen
alignment mode before calling the library.

Asymmetric induction mode has a related unchecked boundary. Accepted shifts can place
`VAL4`/`VAL5` outside `INIT..VAL1`. At 100 kHz, 50% duty, `PreShiftNanos=-250` and
`PostShiftNanos=-500`, the current calculation produces `VAL1=1499` and `VAL5=1574`;
the B reset compare is unreachable and the output can remain asserted.

General sampled waveforms also need a Nyquist/domain check. A modulation frequency at
the carrier produces a 32-bit DDS increment that wraps to zero; values above Nyquist
alias while status can still describe the requested frequency.

Evidence: parent `src/config_serde.h:273-290`, `src/pwm_timing.h`,
`src/pwm_utils.cpp:833-880`; eFlexPwm `src/source/eFlexPwmSubmodule.cpp:165-200`;
i.MX RT1060 RM Rev. 4, FlexPWM 16-bit counters, prescaler and VAL compare registers.

### 4. Make live PWM changes electrically atomic

Disabling the modulation interrupt does not stop the counters or mask the pins.
Sm20-SM23 are reconfigured and given LDOK separately. Compare registers are buffered,
but `OCTRL`, `OUTEN` and `CTRL2[INDEP]` are immediate. A topology, polarity, pair-mode,
dead-time or prescaler change can therefore expose mixed old/new states.

The complementary-to-independent path waits a fixed 200,000 polls for LDOK and then
sets `INDEP` even if the load never happened. At 18 Hz a reload can be 55.6 ms away,
well beyond the tight polling loop, so PWM_B can publish stale active `VAL4/VAL5` data
for the rest of the period.

A narrower but more serious transition is fully reproducible. If Sm22 changes from
complementary/HighTrue to independent while a phase-shifted scheme changes the cell to
LowTrue, eFlexPwm writes immediate `OCTRL.POLA` and `POLB` bits in separate operations.
Between those writes, one half of a logical complementary pair is inverted and the
other is not; a logical `(0,1)` state can therefore reach the pins as `(1,1)`. This is
a potential same-leg shoot-through command, not merely a phase skew.

The `SyncPwm` option is not a remedy. It routes an XBAR signal but does not configure
or start a PIT, select external sync in `CTRL2[INIT_SEL]`, or perform an atomic restart.
It must currently be treated as non-functional/experimental. MTP can also claim PIT0
through `IntervalTimer`, so any future common-start implementation must allocate and
isolate its trigger explicitly.

**Required gate:** separate duty-only updates from topology/timing changes. Stage all
buffered registers, issue one module-wide LDOK, and keep affected outputs in a proven
safe state while changing unbuffered fields. Check every timeout and fail dark.

### 5. Reject malformed configuration rather than replacing omissions with defaults

`POST /api/config` does not call `configDocComplete()` at all. The preset/import check
only verifies four top-level values are non-null; empty objects, scalars and arrays pass.
For example, empty `FaultProtection`, `CurrentLimit` and `Thermal` objects deserialize
to compiled defaults with all three protections disabled.

**Required gate:** define a versioned full-document schema or explicit patch semantics.
Validate object types and every required safety child into a separate candidate object;
only apply after the whole document succeeds. Never interpret omission as “disable a
protection”.

### 6. Add one authoritative pin-ownership validator

Most configurable pins are range-checked weakly or not at all, and they are not checked
against PWM, Wire/Wire2, trigger, fault, ADC, OneWire or each other. A concrete accepted
example is `PowerMon.PgEfusePin=4`: `powerMonitorConfigure()` runs after PWM setup and
`pinMode(4, INPUT)` remuxes SM20 PWM_A to GPIO. `FaultProtection.Pin=255` is logged as
armed although the Teensy core silently ignores the invalid pin.

The PowerMon UI accepts 0-255 for digital and analog pins. Restrict IMON to the actual
analog-capable Teensy 4.1 pins; the pinned Teensy core has a specific pin-42
`analogRead()` table-boundary defect, so pin 42 must never reach it.

**Required gate:** build a central ownership map for every fixed and configurable pin,
validate it before touching hardware, and make conflicts a rejected configuration—not
a silently corrected one.

### 7. Make waveform upload staged, bounded and atomic

The binary TEGW sequence ingest writes a record before checking that it is within the
declared count. A header declaring 64 segments followed by a 65th record writes index
64 past the `0..63` arrays; final-length validation rejects the file only after the
out-of-bounds writes.

The SD streaming double buffer also has an ISR publication race. `markFilled()` clears
`refillNeeded[k]` and only then publishes `valid[k]` in two interruptible stores. If the
carrier ISR lands between them, it sees an empty buffer, emits the previous sample,
marks the same buffer for refill, and can let foreground code rewrite it while the ISR
consumes it.

An authenticated live upload can also rewrite or reset storage still used by the ISR
for no-SD sample-step, SD-resident sample-step and SD-streamed playback. All upload
modes service only the watchdog, not feedback, PLL, thermal, metering or MPPT. Temporary
TCP no-data is judged with a CPU iteration count rather than Content-Length plus a
wall-clock deadline.

**Required gate:** reject excess records before every write; upload and verify into a
separate buffer/file; prohibit replacement while generating or enter a defined safe
output state; switch stores only at a carrier boundary; use byte and time budgets for
the stream.

### 8. Correct soft-start and low-rate PLL boundaries

Soft-start uses an integer Q15 step. If `target / requestedCycles` rounds to zero it is
forced to one, so a full-scale ramp can never exceed about 32,768 carrier cycles. A
requested 60 s ramp therefore completes in about 1.64 s at 20 kHz and 0.164 s at
200 kHz. This is unsafe if the setting is relied on for inrush control.

The PLL validator permits a carrier only 18 times nominal. At 1 Hz nominal / 18 Hz
carrier, the 20 ms amplitude estimator has `lambdaA = Ts/0.02 = 2.78`, an unstable
pole, and its signal-loss/unlock dwell counts truncate to zero. Backlogs are drained at
most 4,096 samples per pass. A remaining backlog is re-anchored on the next pass using
the newest global DDS increment even though those samples were captured under the old
increment; at 200 kHz the affected accepted range starts at 4,097 samples (~20.5 ms)
and extends to the 50,000-sample discard threshold.

**Required gate:** use a fractional/time-based ramp accumulator; give every discrete
filter a proven sample-rate range; force dwell counts to meaningful minima; and add
batch/backlog tests at every supported carrier boundary.

### 9. Remove blocking work from the supervisory control schedule

Several operations keep PWM hardware running while loop-side protection/control is
stale:

- MTP is permitted during ordinary SPWM, resident waveforms, fixed duty and outputs on
  other modules; one host operation can occupy one `MTP.loop()` call for seconds.
- QNEthernet `hostByName()` can synchronously wait its default five seconds on failed
  DNS without servicing `serviceControlTasks()`. At 20 kHz both 16,384-sample stream
  buffers cover only 1.6384 s, so playback can hold the last sample for more than
  three seconds. Failed Influx resolution is retried at every metrics interval.
- MQTT can add bounded connect/CONNACK waits.
- OneWire globally masks interrupts for 65-70 microseconds in individual slots, longer
  than one 20 kHz carrier period. ROM caching reduces the number of slots, not their
  worst-case interrupt latency.
- At 1 MHz, the accepted 12-bit high-speed ADC configuration itself takes 32 ADC
  clocks, about 0.853 microseconds at 37.5 MHz. That leaves only about 0.147
  microseconds (88 CPU cycles) to service two results, update rings and 64-bit meter
  accumulators, and restart both ADCs. An ISR overrun was not proved—the code can
  instead skip samples when conversion is incomplete—but the firmware exposes no
  ADC-skip counter and has no bench evidence for this combination.

**Required gate:** asynchronous network state machines; explicit maintenance mode for
MTP; hardware-assisted or scheduled OneWire access; feature-aware carrier limits; and
DWT high-water/missed-sample release criteria for every supported combination.

### 10. Treat PSRAM as a mandatory, tested component

The image statically allocates 7,341,056 bytes in EXTMEM. Teensy 4.1 only provides pads
for optional PSRAM; the chip is not intrinsic board RAM. Boot tests 1 KiB, logs failure,
and continues. `waveformLoadFromSd()` runs before that token test.

**Required gate:** check the core's detected external-memory size before any EXTMEM
consumer, run a suitable manufacturing/boot memory test, and keep outputs inhibited if
at least 8 MiB is not present and healthy.

## Security and recoverability blockers

### Unsigned, single-slot OTA

CRC and image-structure checks prove transfer integrity, not publisher authenticity.
Anyone holding the shared PIN can install any structurally compatible image or roll
back to a vulnerable one. HTTP carries that PIN in cleartext.

The RT1062 copy-down overwrites the sole boot image. Power loss after the first erase
requires physical Program-button recovery. If all three readback attempts fail, the
code returns after disabling ENET and USB IRQs and after damaging the base image;
comments claiming the device remains remotely reachable are false. The safe behaviour
is a terminal outputs-off state with an explicit physical-recovery procedure.

Before any non-lab deployment, use signed manifests/images with anti-rollback. A truly
recoverable unattended updater needs an immutable first stage and A/B or equivalent
storage architecture.

### Authentication and input handling

- No TLS protects HTTP, MQTT or InfluxDB credentials.
- PIN generation fails open: an empty PIN authorises every write if TRNG or persistence
  fails. `saveConfiguration()` returns no result, and the current “persisted” test only
  checks that the RAM copy is non-empty.
- Replacing a longer live PIN with a shorter one leaves non-zero tail bytes because the
  destination is not cleared; constant-time comparison then rejects both PINs until
  reboot.
- aWOT accepts a negative `Content-Length`. In the unauthorized OTA body drain,
  `Request::available()` remains negative (therefore true) after peer close and the
  loop has no terminating transition.
- A full first `X-Auth-Pin` plus a duplicate header writes one terminating NUL one byte
  beyond the registered buffer. It is not an authentication bypass in this exact ELF,
  but it is network-reachable undefined behaviour.
- Every GET remains unauthenticated, including captures, logs, crash reports, preset
  names and topology.
- Secrets are plaintext in `/settings.cfg` on removable SD and are readable through
  MTP when enabled.

Ordinary cross-origin JavaScript cannot set `X-Auth-Pin` without a successful CORS
preflight. The older claim that merely visiting any web page can issue authenticated
writes was too broad. Empty-PIN operation, cleartext disclosure/replay, DNS rebinding,
missing Host/Origin policy and unauthenticated reads remain real concerns.

### Configuration persistence is not recoverable

The temporary file is fully written before the live file is removed, which narrows the
failure window, but FAT remove+rename is not atomic. Power loss or rename failure after
`sd.remove(filename)` leaves no live settings file. Boot does not recover a valid
`.tmp` or backup; the next save removes the leftover temporary file. Save returns
`void`, the pending flag is cleared before the attempt, and HTTP success only means the
hardware apply completed—not that settings reached stable storage.

On boot after that remove/rename failure window, defaults contain an empty PIN.
`writePinEnsure()` generates a replacement and calls the same save path, which deletes
the complete recoverable `.tmp` before writing defaults plus the new PIN. Its reported
“persisted” result only tests the non-empty RAM string.

Use two generation-numbered, CRC-validated slots (or live+backup with verified recovery),
return and publish the persistence result, and retry failures without losing the last
known-good configuration.

### NTP timestamps are not trustworthy

The NTP request carries no transaction value and the response is not checked for
source IP/port, server mode, leap state, stratum, or matching originate timestamp.
Unsigned epoch subtraction also maps NTP seconds zero to a plausible 2036 Unix value.
A stray or forged LAN datagram can therefore set the battery-backed RTC and event-log
chronology. Follow RFC 5905 request/response association and sanity checks.

## Driver-board power-monitor review

The INA226 calibration, current scale, bus-voltage scale and power LSB match the TI
datasheet. The following do not:

1. `0x4927` encodes **128 averages**, not 16. With 1.1 ms shunt and bus conversions,
   the result period is 281.6 ms, not 35.2 ms. The 100 ms poll usually rereads the same
   conversion. `0x4527` is the corresponding 16-average value.
2. A positive shunt-overvoltage threshold is signed two's-complement. The helper clamps
   at `0xFFFF` instead of `0x7FFF`. With the default 10 milliohm shunt, 8,192 mA becomes
   `0x8000` (-81.92 mV) and 10,000 mA becomes `0x9C40` (-63.84 mV). A zero or positive
   shunt reading exceeds these negative limits, so SOL effectively reasserts after each
   conversion.
3. `AlertPin` is configured as an input but never read or attached to an interrupt.
   AFF polling works only while I2C is healthy; an I2C recovery resets the INA226 before
   reading the old latch and loses that history.
4. The first valid sample after a communications gap is integrated across the whole
   unobserved interval, backfilling energy with a value that was not measured then.
5. TPS25983 IMON gain is specified over the datasheet's stated current range; below it,
   treat IMON as a qualitative cross-check and the INA226 as the reference.
6. Power-monitor polling is deliberately absent from `serviceControlTasks()`, so long
   handlers can miss PG edges and create additional energy-timestamp gaps.

Sources: TI INA226 Rev. B, Tables 7-3 through 7-7 and Mask/Enable semantics;
TI TPS25983 Rev. C electrical characteristics and IMON design guidance.

## Other confirmed correctness and observability gaps

- `captureActive()` can be true while fixed/basic PWM has no SM20 modulation ISR, so
  no samples arrive; meter/PLL stay empty and IMON is unnecessarily suppressed.
- ACMP filter controls affect the signal selected for XBAR when `COS=0`. With
  `FILTER_CNT=7`, `FILT_PER=255`, 150 MHz IPG and the datasheet's 40 ns maximum
  high-speed propagation, the comparator path can take about 11.947 microseconds,
  before additional XBAR/FlexPWM output-disable propagation. This is not the raw
  comparator's approximately 25 ns typical delay. Publish and constrain the complete
  measured trip latency; use continuous mode for the fastest PWM-fault path.
- Dead-time compensation is applied even where the pair mode inserts no hardware dead
  time, uses Sm20's value for every cell, and uses voltage-reference sign rather than
  measured phase-current polarity.
- Two-leg THIPWM retains the injected third harmonic in the differential output; the
  familiar triplen cancellation applies to three-phase line-line voltages. Document the
  actual topology and spectrum.
- THD searches harmonics around multiples of a rounded fundamental bin with only a
  one-bin radius. High-order harmonics are badly under-reported for non-coherent
  captures; use fractional-bin prediction/coherent resampling before standards-style
  claims.
- Accepted extreme meter scale factors can convert a finite power value outside
  `int32_t`; the float-to-integer conversion is undefined and can feed bad values into
  MPPT. Validate and saturate every derived quantity.
- Meter and PowerMon energy timestamps are not advanced while capture is inactive/
  fault-frozen or I²C is offline. The first recovered power value is integrated over
  the whole gap; a one-hour outage followed by a 1 kW reading falsely adds 1 kWh.
- Thermal probe roles follow OneWire ROM search order, not connector identity. A
  different-ROM replacement of a cached sensor is not adopted without reboot/pin
  change, and rediscovery can swap hot/cold role order.
- The current Ethernet MAC and `teg.local` name are fixed for every unit; two devices on
  one LAN collide. Derive per-device identity from the Teensy serial/MAC.
- The PowerMon `AlertPin` setting is currently dead configuration.

## Build, CI and performance notes

- The final Teensy compile command is authoritative. It contains `-std=c++23` followed
  by `-std=gnu++17`, and `-O3` followed by `-O2`; ARM GCC therefore builds as GNU++17/
  O2, not the requested C++23/O3. Remove the later defaults with `build_unflags`, then
  rebuild/test the intentionally selected release flags.
- The successful firmware build is not warning-clean. Current warnings include PLL

## Findings deliberately rejected or narrowed

- **Retracted:** a claimed “25/26 sanitizer suites passed.” The available Windows
  toolchain could not link ASan/UBSan; only the targeted WSL HEX-parser reproduction
  above is valid evidence.
- **Narrowed:** `hexParseLine()` can read one byte beyond a short string's NUL under
  its generic API contract. Production OTA supplies a zero-filled 600-byte object, so
  no production allocation escape was reproduced.
- **Rejected:** first-boot PIN generation necessarily calls an uninitialised TRNG.
  QNEthernet's global object initializes its entropy source before `setup()`; explicit
  failure-open and false persistence reporting remain real.
- **Rejected:** eFlexPwm debug logging in the ISR. It is macro-disabled at the recorded
  gitlink; phase-shift debug code is not linked into this image.
- **Rejected:** a generic INA226 integer-overflow claim. The current raw scaling
  products fit their declared integer widths; the separate meter-calibration output
  cast remains a real boundary issue.
- **Rejected:** a generic invalid-digital-pin memory-corruption claim. Teensy digital
  APIs guard invalid pins. The specific analog pin-42 table boundary and pin-remux
  conflicts remain.
- **Rejected:** missing DMA cache maintenance for the capture/waveform rings. Current
  consumers are CPU/FIFO based, not DMA producers.
- **Rejected:** the historical OTA zero-length Intel-HEX erase underflow; the explicit
  zero-count/bounds guard is present.
- **Rejected:** the previous ACMP FFULL/FHALF teardown and fault-clear/retrip races;
  current code preserves a recovery boundary and rearms the IRQ last.
- **Rejected:** raw capture download necessarily freezes controls; its chunk path now
  calls `serviceControlTasks()`.
- **Rejected:** MTP has a surviving write bypass. The dispatcher and filesystem adapter
  both refuse mutation; partial-read/truncation handling is still a robustness issue.
- **Rejected:** MQTT still uses PubSubClient's 15 s socket timeout. Firmware sets two
  seconds; DNS and aggregate blocking remain.
- **Narrowed:** live waveform storage races affect sample-step and streamed playback,
  not period-mode custom or copied sequence playback. All upload modes still stall
  control tasks.
- **Narrowed:** OneWire does not mask interrupts for its full 480 microsecond reset-low
  pulse. Its 65-70 microsecond critical sections are sufficient to exceed a 20 kHz
  carrier period. The aggregate programmed masked time for two addressed reads plus a
  conversion request is roughly 5.2-12.2 ms depending on ROM bits, with interruptible
  gaps between the short critical sections; `thermalMissedCycles` excludes the request
  and rescan work.
- **Narrowed:** a 1 MHz carrier does not prove that the PWM ISR itself overruns. The
  accepted dual-ADC path can instead miss conversions silently. Release support still
  requires DWT measurements and an ADC-skip counter.
- **Rejected:** the 128-average INA226 setting necessarily delays SOL by 281.6 ms. TI
  evaluates the shunt alert after shunt conversions; the 281.6 ms figure applies to
  refreshed averaged measurement results.

## Required release sequence

1. Implement a boot output inhibit, active-level fault check, watchdog/start policy,
   canonical carrier, representable timing validation, and atomic topology updates.
2. Add strict configuration schema and central pin ownership validation.
3. Bound/stage waveform ingest and fix all network-reachable OOB/liveness defects.
4. Fix soft-start, PLL sample-rate/backlog, meter saturation, and feature-aware carrier
