# TEG adversarial review — 28 August 2026

Review only. No firmware patches in this pass. Size figures are the last
**recorded** post-hardening numbers, not a live `pio run` of this tree.

**Verdict:** the inverter loop is already safety-hardened (inhibit stack,
polarity-before-MASK, complete-document apply). It is **not** lean. One
`MainConfig` and one 8 s watchdog share a superloop with HTTP, MQTT, Influx,
MTP, OLED, OneWire, a 7.3 MiB PSRAM reservation, and a 4096-point spectrum
GET. “Lean” means **cut I/O and compile-time width**, not delete SPWM.

The realistic starve path on a generating bench box is **stats.html at 250 ms
with spectrum auto-refresh**, plus an Influx miss or MQTT reconnect — not
MTP-while-generating (`MTP.loop()` is already withheld). The hardware
ACMP→XBAR→FAULT0 path has the right shape and is **unconfirmed on this
board**. Host tests do not see OUTEN, LDOK, or the trip.

## Ranked findings

### P0 — can miss a carrier or trip on a live stage

| ID | Finding | Where | Evidence |
|---|---|---|---|
| P0-1 | OneWire globally masks the modulation **and GPIO fault** ISRs | `src/thermal.cpp`, `src/config_serde.h` | Dallas write-0 is 65–70 µs. The 10 kHz carrier cap avoids a full missed reload; it does **not** preserve the claimed ~1 µs GPIO trip. ACMP hardware gates FlexPWM1 SM3 and FlexPWM2 only — Tm3/Tm4 stay software-only. |
| P0-2 | 200 kHz ISR + dual-ADC is a budget, not a WCET | `IsrOverflowSm20`, `captureTick` | One pass can do 4-cell duties, dither VAL rewrite, 2–4× `PWM_UpdatePwmDutycycle`, LDOK, dual ADC, two EXTMEM stores, meter MAC, CBC poll. ADC alone is ~0.85 µs documented. Worst-case 4-cell + meter + PSRAM miss is **unproven**. |
| P0-3 | Hardware FAULT0 path is unconfirmed | `src/acmp.cpp`, `docs/BENCH_CHECKS.md` §3 | CMP→XBARA1→private FAULT0 is the only trip with the right shape. `OPE=0`. README says not bench-verified. GPIO ISR is still software. |
| P0-4 | Kitchen-sink I/O shares the trip MCU | `src/main.cpp`, `platformio.ini` | HTTP, MQTT, Influx, MTP, SD, OLED, OneWire, and PWM live in one image under one 8 s WDOG. `serviceControlTasks` keeps PWM/PLL/meter alive during HTTP **writes**; it does **not** run during JSON/FFT build, MQTT CONNACK, Influx drain, or an MTP transfer. |
| P0-5 | `releaseOutputInhibit` can undo a concurrent fault ISR | `src/pwm_utils.cpp` | Samples GPIO/ACMP once, then `restoreCellPolarity` → `Tm*.enable()` → `connectConfiguredOutputDrivers`. If a fault ISR masks after the check, the interrupted release resumes and reconnects. A still-asserted GPIO need not generate another edge. Fix before any energised run. |

### P1 — delays the control pass or spends budget that is not earned

| ID | Finding | Where | Cut / gate |
|---|---|---|---|
| P1-1 | Stats poll fans out three HTTP requests | `web/stats.html` `poll()` | No in-flight lock. At 250 ms that is up to 12 new requests/s against a 4-slot / 8-PCB pool. Floor poll at 1–2 s; default spectrum **off**; one in-flight request. |
| P1-2 | `/api/spectrum` is the heaviest recurring handler | `src/web_handlers.cpp` | Default 4096-pt FFT, then a 512-float `JsonArray`. ~40 KB `DMAMEM` always resident. Compute is ~2 ms; heap + JSON + TCP are the cost. Default `points≤1024`, emit ≤128 bins, or a PIN-authed binary body. |
| P1-3 | MQTT CONNACK can freeze `loop()` ~2 s while generating | `src/mqtt.cpp` | DNS is gated on inhibit; CONNACK is not. 2 s @ 20 kHz ≈ PLL resync + stream underrun. Gate connect like DNS, or compile MQTT out of an energised image. |
| P1-4 | OLED flush can exceed the PLL backlog at high carrier | `flushDisplay` every `loop()` | 25–30 ms I2C vs 20.48 ms backlog cap @ 200 kHz. Raise flush to 1 s, skip while generating, or compile OLED out. |
| P1-5 | Influx connect + 250 ms drain | `src/utils.cpp` | 500 ms connect + 250 ms drain + `String` copy of a 560-byte line, after control tasks. Skip the drain (or cap ~20 ms); take `const char*`. |
| P1-6 | `delay(1)` plus default `Feedback.LoopHz = 1000` | `src/main.cpp`, `src/config_json.h` | Work plus a 1 ms sleep makes a 1 kHz PI structurally miss. Due-aware `yield()` (QNEthernet still needs a yield). Default LoopHz **250**. |
| P1-7 | PWM release requires 8 MiB PSRAM after a 1 KB `0xAA` probe | `src/memory_utils.cpp` | Checks only `buf[0]` and `buf[1023]`. Under `-O2 -flto` those reads after `memset` may be eliminated. The ISR then walks 7.3 MiB of unproven EXTMEM. March the used range with volatile/cache-maintained reads, or drop the interlock on a lean env. |
| P1-8 | USB MTP is in every binary | `platformio.ini` `-DUSB_MTPDISK_SERIAL` | Runtime `Mtp.Enabled` defaults false. Composite, PID `0x04D5`, and core MTP objects still compile. Host still sees MTP. Contested: see [Default image](#default-image). |
| P1-9 | OTA is compiled out of *behavior*, not of the image | `src/ota.cpp`, `web/index.html` | POST returns 501. Routes, `flash_ota.cpp` (`FASTRUN` commit), and the settings article still link. `#ifdef TEG_ENABLE_UNSAFE_LAB_OTA` the compile units. |
| P1-10 | `/api/capture` `count` is unclamped | `api_capture` | Defaults to 20,000; can walk the full 1 M-sample ring before write callbacks. Clamp (e.g. 32 k). Raw already chunks with `serviceControlTasks`. |
| P1-11 | `applyPwmConfig` always re-runs capture / thermal / PLL | `src/pwm_utils.cpp` | A telemetry edit is electrically a reconfigure. Four FlexPWM modules go through disconnect → LDOK → inhibit-all-on-any-module-failure. |
| P1-12 | Pico CSS is ~37% of embedded UI | `web/pico.min.css` | 11,640 B gzip. Both pages already carry layout CSS. ~2 KB of tokens would save ~12 KB flash and first paint. |
| P1-13 | Settings load is five API calls | `web/index.html` | `/api/config`, presets, waveform, `/api/ota`, then 1 Hz status. Skip OTA in prod; defer waveform/presets until those panels open. Slim status for the 1 Hz paint. |
| P1-14 | Preset/import publishes `config` with the wrong IRQ gate | `src/presets.cpp` | Uses `spwmActive()` to disable/re-enable PWM2 IRQ. Capture and CBC also need that IRQ (`pwmInterruptRequired`). Fixed-duty→SPWM can memcpy a live `MainConfig` while the ISR is running. Web config already uses the correct helper. |
| P1-15 | Thermal protection fails open | `src/thermal.cpp` | Missing probes are dropped. No valid reading → derate **1000** (full output). First harvest is ~2.8 s after `setup` can release PWM. A hot restart or lost heatsink can run full power on die temp only. |
| P1-16 | Waveform promotion checks file length, not payload | `src/waveform.cpp` | Sequence writes and the header `seek`/`write`/`flush` are unchecked. Read-back is `fileSize() == expectedSize`. A failed header rewrite can still promote. Add CRCs; verify parse before swap. |
| P1-17 | Out-of-range current-limit is silently replaced and ACK'd | `src/config_serde.h` | Threshold outside 100–3300 mV becomes **2475 mV**. Import/web log “corrected” and persist success. Operator can believe a low trip was accepted. Strict 422 for API/import; sanitize only on legacy boot. |
| P1-18 | Import pastes real secrets onto imported endpoints | `src/presets.cpp` `restoreSecrets` | File cannot *set* a password, but it can change host/port. The device then sends the stored MQTT password / Influx token to that address. Preserve a secret only when the endpoint identity is unchanged. |
| P1-19 | MTP `GetObjectHandles` uses a host StorageID without a store bounds check | `scripts/mtp_core162/MTP_Teensy.cpp` | `Storage2Store` then `isMediaPresent(store)` with no `store < get_FSCount()`. Other opcodes do the same. Maintenance-only, but USB-reachable. Validate before every index. |
| P1-20 | Dynamic `MTP.begin()` can leave the 20 Hz FS timer armed across a release | `src/mtp_service.cpp` | `mtpTask` returns immediately after `begin()`. A same-pass fault-clear can release PWM; later passes see `!inhibited` and skip the first `MTP.loop()` teardown. End the timer before OUTEN, or refuse release until MTP is quiet. |

### P2 — safe slims and leftover chrome

Safe on host tests (no bench):

- Delete unused `include/defines.h`, `printDigits`, `enableXbar` (never called; `SyncPwm` already forced false).
- Stop serializing `Pwm.SyncPwm`, `CurrentLimit.FilterCount` / `FilterPeriod` after one compat release; keep the `validateConfig` clamps.
- Serialize one carrier frequency, not four cell mirrors that are overwritten.
- Remove the dead-time-compensation checkbox and the CMSIS engine dropdown (path compiled out).
- `#include <arm_math.h>` only under `TEG_ENABLE_CMSIS_FFT`.
- Drive OLED from `EventLog` instead of a second `String logs[5]` heap ring.
- `getStackLowWater()` only samples at the few call sites (`src/utils.cpp`). Deep HTTP/gzip/MTP has already unwound. Paint unused DTCM and scan a watermark if the RAM1 claim must be evidenced.

Needs bench if removed: Adafruit OLED stack, dual MQTT+Influx, always-on MTP USB,
always-resident FFT / gzip / stream buffers, 2+1 MiB capture rings, OTA compile
units, four-module apply copies, named presets vs export.

## Default image

Reviewers agree on the **cut order**: dead chrome → poll honesty → cheaper
spectrum → compile-time flags → buffer placement. They **disagree** on the
default USB type and whether `teensy41` stays the kitchen sink.

| Position | Default env | USB | PSRAM to release PWM |
|---|---|---|---|
| Architect (lean program) | Full `teensy41` stays the CI size gate; add optional `teensy41-pwm` | Keep bare `-DUSB_MTPDISK_SERIAL` | Keep mandatory 8 MiB |
| Design challenge | Default **lean**; today’s image is `teensy41-lab` with the stage disconnected | CDC only (`USB_SERIAL`) | Not required for scheme 0 / SPWM |
| I/O review | Same as design for USB | Compile `USB_SERIAL` unless MTP is a lab flag | (out of scope) |

**Merge recommendation:** keep **schemes 0 / 1 / 3 / 6** in any energised
image (they never invert a cell). Do **not** delete the LUT. Put MTP, MQTT,
Influx, spectrum, 2 M-sample AWG, and polarity-inverting schemes 2 / 5 / 4-POD
behind a lab env or `TEG_WITH_*` flags. Keep the full image as the CI size
gate so the fat hex cannot regress unnoticed.

Do **not** write `-DUSB_MTPDISK_SERIAL=1`. The Teensy builder token-matches
the bare flag; `=1` silently enables both USB modes and MTP disappears.

## What to cut / gate / rate-limit

**Cut (host-testable or flash-only)**

- Pico CSS → small custom sheet
- OTA UI, routes, `flash_ota` / ingest unless `TEG_ENABLE_UNSAFE_LAB_OTA`
- CMSIS dropdown
- Dead symbols and schema listed under P2
- Merge `GET /api/config/export` into `GET /api/config?download=1`

**Gate (compile-time, defaults = today’s full instrument until a lean env exists)**

- `TEG_WITH_OLED`, `TEG_WITH_THERMAL`, `TEG_WITH_MQTT`, `TEG_WITH_INFLUX`,
  `TEG_WITH_SPECTRUM`, `TEG_WITH_POWERMON`
- USB MTP as a **whole env**, not a runtime bit
- Spectrum auto-refresh default **off**; no 250 ms poll

**Rate-limit / cheaper I/O** (only new I/O that *reduces* load)

- Binary spectrum (fixed header + `uint16` bins); keep PIN + subnet + Host/Origin
- Spectrum: `points≤1024`, `bins≤128`, cadence ≥2 s, one in-flight request
- Slim `/api/status?lite=1` for the 1 Hz paint
- Influx: `const char*` + no 250 ms drain
- Serialize stats polls (status → log → spectrum)

Do not add TLS, command MQTT, extra dashboards, CMSIS-on-by-default, or A/B OTA.

## Do not touch without a scope

| Item | Why |
|---|---|
| FlexPWM LDOK / `LDMOD=0` / FULL reload | Immediate load can latch a high-side on |
| `PWM_UpdatePwmDutycycle` / VAL2–5 geometry | Wrong VAL pair is shoot-through |
| MASK / FAULT0 pre-polarity un-invert | Already a device-killer on paper once |
| Fault IRQ prio 16 vs PWM 32 | Trip must beat the carrier |
| Bare `-DUSB_MTPDISK_SERIAL` token form | `=1` breaks MTP |
| `-fno-strict-aliasing` with LTO | Teensy USB serial-number types |
| Global `-O3` / `TEG_ENABLE_CMSIS_FFT` | Measured / documented RAM1 miss |
| MTP write refuse + `mtpKickWatchdog` | Unpatched GetObject resets a live inverter |
| `serviceControlTasks` exclusion of web/MQTT/MTP | Re-entrancy on the same lwIP client |
| `validateConfig` clamps (SyncPwm, DTC, ACMP filter) | Slim the schema/UI, not the refuse logic |
| Secret redact / preserve / restore | PIN, MQTT password, Influx token |
| `delay(1)` **yield contract** | QNEthernet services lwIP from `yield()`. Prove a due-aware yield before deleting the call. |
| PSRAM interlock (until a lean env exists) | Unproven chip must keep drivers off |

## Recommended program (order)

0. **Races first (Codex)** — fix `releaseOutputInhibit` vs fault ISR, and preset/import IRQ gating (`pwmInterruptRequired`, mask before `memcpy`). Do not energise until both are independently reproduced.
1. **Safe slims** — dead files/symbols, dead schema/UI, CMSIS picker, `arm_math.h` guard.
2. **Poll honesty** — kill 250 ms; spectrum auto off; LoopHz default 250; OLED flush 1 s; PowerMon 250 ms; thermal harvest 4 s when carrier ≥ 10 kHz; RAM Serial 30 s or `Pwm.Verbose` only; clamp `/api/capture`. Do not change the PLL 250 ms lock-drop or the MPPT ≥ 2.1 s floor.
3. **Cheaper spectrum** — default 1024 points, ≤128 bins, optional binary body; keep PIN middleware.
4. **`teg_features.h`** — flags default **on** so native tests and `teensy41` stay valid; `lib_ignore` when 0.
5. **MTP `FLASHMEM`** on cold 1.62 command paths only; timer teardown and copy kicks stay ITCM.
6. **Buffers** — FFT / gzip / stream toward EXTMEM or on-demand; do not shrink stream depth below 8 K samples without an underrun test.
7. **Decide the default image** — full `teensy41` + optional `teensy41-pwm`, or lean-default + `teensy41-lab`. CI size gate stays on the fat image either way.
8. **Bench** — `docs/BENCH_CHECKS.md` preflight + §0 / §0a / §3 **before** any energised change to apply, polarity, or FAULT0.

Per-function `-O3` on `IsrOverflowSm20` / `modulationCycleDuties` only after a
DWT prove. Header `constexpr` defaults must stay today’s values or native
Unity (`test_build_src = no`) tests a different machine.

## Features that earn keep vs features that do not

**Earn keep (bench workflow, small, already tested)**

- Scheme 0 / 1 / 3 / 6 and the 2048-point LUT
- Hardware trip *once scoped*, GPIO trip, fail-dark apply
- PIN + subnet + Host/Origin on `/api/*` (do not add a LAN-trusted bypass)
- Portable radix-2 FFT as an **on-demand** diagnostic
- Capture **raw** binary (`TEGC`) already exists — do not poll JSON envelopes
- Loop-pass DWT split on `/api/status` (`loopUs` / `webUs` / `mtpUs` / `controlUs`) — the one new field that *reduces* guesswork
- `featureBits` boot banner so “MQTT is off” is not confused with “still linking”

**Do not add until bench passes**

- New polarity-inverting schemes, “true” PSPWM / RT1170 work
- Grid-tie / anti-islanding / HA energy-dashboard **claims** (PLL+MPPT is a bench toy)
- MQTT command topics
- Larger EXTMEM, CMSIS default-on, dead-time compensation, `SyncPwm` revival
- Window comparator / FAULT1 as a feature before FAULT0 is seen
- TLS-as-if-product, signed OTA, SunSpec, AFCI

## Architecture snapshot

Single-core superloop. Hot path is **one** FlexPWM2 SM0 reload ISR
(`IsrOverflowSm20`, NVIC 32) plus fault IRQs at priority 16. Everything else
is cooperative.

| Class | Paths | Blocks loop? |
|---|---|---|
| Hot | `IsrOverflowSm20`, ACMP/GPIO fault | Preempts |
| Warm | feedback, PLL, meter, MPPT, ACMP task, stream | Interval-gated |
| Warm-hostile | OneWire thermal | 65–70 µs IRQ mask / bit |
| Cold | HTTP (one request/pass, 30 s write budget), MQTT, Influx | Yes; HTTP writes call `serviceControlTasks` |
| Maintenance-cold | MTP | Whole `MTP.loop()`; withheld while generating |

Memory: `FASTRUN` ISR/trip in ITCM; `spwmLut[2048]` and ISR volatiles in DTCM;
FFT / event log / gzip / stream in OCRAM (`DMAMEM`); 2+1+4 MiB rings in
EXTMEM. Cold HTTP/MQTT/setup is `FLASHMEM`.

`MainConfig` is a process-wide bus (`extern` in 15 files). Apply entries are
duplicated (`api_config_post` `preserveSecrets` vs `configApplyDocument`
`restoreSecrets`). Unused leftovers: `attachInterruptVectors`, `enableXbar`,
`Pwm.SyncPwm` (always stripped).

Open questions from the architecture map: is FlexPWM1 SM3 still a wanted
power-stage pair, or does it only force Tm1 into every apply? Can Tm3/Tm4 /
asymmetric SM42 leave the default image? If `MTP.begin()` is deferred until a
later inhibit, can SD save / stream race the 20 Hz IntervalTimer? QNEthernet
is AGPL — the Ethernet stack is not a disposable leaf.

`TEG_WITH_MTP_SERVICE=0` only skips project `MTP.begin()` / `MTP.loop()`. The
USB descriptor stays composite (PID `0x04D5`) while `-DUSB_MTPDISK_SERIAL` is
set. That is confusing Explorer, not a write hole — do not “fix” it by writing
`=1`.
